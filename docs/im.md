# 从即时消息发起任务

卡的吞吐是有限的。聊天入口不改变这件事。它只把「发起一次任务」收成一条消息，并把六段提示词退回来。

v0 的这条入口**只做 dry-run**。一部片子的真渲染要数小时，不能占着一条聊天连接等画面。`执行：正式` 会被拒绝，任务不会进 ComfyUI 队列。

## 消息

```
跑 sample-paper-boat
```

已有语料用故事 id。新文本：

```
跑
标题：台阶上的灯
体裁：有趣
正文：
虚构。陈舟把一盏不肯随便亮的灯挂到窄巷，守到天明就收走，不往下写成连载。
```

体裁可以写新闻、感人、有趣。正文至少 20 个字，并且你得有权拿它来改编。

回复里有片名、计划时长、通过和隔离的镜头数，以及第 1 镜的六段提示。接着发：

```
提示 s003
状态
帮助
```

`提示` 不带运行号时，看最近一次从即时消息发起的任务。

## 本机服务

仓库不绑定某一家聊天软件的 SDK。飞书、Slack、Telegram、钉钉或别的工具，只要能把用户发来的文字 POST 过来，再把 `reply` 发回去就行。

```bash
cine serve --config config.example.yaml
```

默认只听 `127.0.0.1:8787`。

```bash
curl -s http://127.0.0.1:8787/tasks \
  -H 'Content-Type: application/json' \
  -d '{"text":"帮助"}'
```

也可以直接 POST 纯文本。`GET /health` 用来探活。

设了 `CINE_IM_TOKEN`（或配置里的 `im.token`）之后，请求要带 `Authorization: Bearer <token>`。口令留空时不校验，只适合本机。不要把空口令的服务暴露到公网。

同一条消息会等到 dry-run 把提示词写完再回复。机器人一侧把超时放到一两分钟就够。真要上 GPU，仍然走以后的批处理，不走这条连接。
