# 流程

一条故事按下面的顺序走。渲染器是后端，不是阶段图本身。

1. **摄入。** 从语料适配器读条目。v0 能读目录里的 JSON，也能导入 SQLite。每条有 id、标题、体裁（`news` / `touching` / `interesting`）、原文、可选标签和权利说明。换数据库时实现同样的 `list_items` / `get` 即可。
2. **改编。** 规则改编器写出约五分钟的剧本、视觉圣经和分镜。时长按 24fps 的 `17n+5` 吸附，总长锁在约 300 秒。原文可以提供由头，连续 18 个字重合会被拒绝。入口可以是几个关键词，或一段社会新闻、感人小品、有意思的小事。输入越短，补上的情节越多，但时长、单集边界和不许乱编的事实先锁住。这一层可以以后换成语言模型；v0 的 `llm` 后端会明确失败，不会偷偷访问网络。

产物写在 `screenplay.json` 的 `expansion` 里，再进入现有定妆、Qwen / H3 提示词和审核，不另开剧本系统。

- `input_kind`：`keywords`、`paragraph` 或已经写好的 `prepared`。
- `locked`：时长约五分钟、一部短片不是连续剧、单人入画。新闻另外锁住：不补写输入里没有的真实姓名、机构、事件结果和数字。
- `gaps`：缺什么就写明。关键词之间的过程是补出来的情节。新闻缺数字、结果或机构时，成片用虚构人物和普通街角，不写成已经核对过的报道。
- 五场节奏：开场、触发、发展、转折、收束。每场一句对白，分镜时长仍落在 `17n+5`。
3. **素材。** 为入画角色的服装变体和场景生成静帧，并给出版本。画外人物只留在圣经里，不进参考图。静帧一改版，依赖它的镜头会被标脏，需要重渲染。
4. **渲染。** 每个镜头先做首帧并自动审核，通过之后才做视频。视频只带这一镜声明的参考图和这张首帧。默认 2 到 3 次 take（示例配置是 3）。尾帧只在同一场、同一动作组里延长动作，不跨场景，也不做反打。
5. **审核。** 结构化报告才是裁判。检查分辨率、时长网格、首帧锁定、参考图范围、脸版本、手部特写、他/她撞车、台词堆叠、静音、基础画面缺陷和六段提示。渲染进程退出码 0 不算通过。
6. **合成。** 按顺序拼接已通过的镜头，写字幕和响度目标。dry-run 只写 `concat_plan.json`、`subtitles.srt` 和 `film_sidecar.json`，不写画面母带。
7. **循环。** 台账记下完成或隔离的故事，下一条继续。一条故事抛错，只隔离这一条。进度写在运行目录里，中断后用 `--resume` 接着跑；已验收的镜头不重做。

监督模式可以在「剧本和首帧之后」以及「审核之后」记停点。dry-run 只记停点并继续。真正停住要同时是监督模式、不是 dry-run，并且带上 `--supervise-block`，然后在运行目录放一个 `CONTINUE` 文件。

默认的研究跑法是 `unattended`：不停下来等人。
