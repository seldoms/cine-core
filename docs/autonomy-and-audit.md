# 自主模式和审核

## 模式

`unattended` 是批处理的默认，也是这个仓库的研究方向。阶段之间不等人点。审核通过就收下；失败就重拍；次数用完就改一版再拍；还是失败就把这个镜头隔离。隔离的镜头太多，或比例超过配置，就把整部片子隔离。无论哪种，循环都继续下一条故事。

`supervised` 是给人想看一眼时用的模式，不是产品论点。dry-run 会把停点写成 `pauses/*.json` 然后继续。要真的停住，使用非 dry-run 的监督模式并加上 `--supervise-block`，再在运行目录创建 `CONTINUE`。

v0 在没有 GPU 的批处理里拒绝直接向 ComfyUI 提交。原因是这一版还收不回可靠的画面文件，不能把整夜循环推进真实队列。

## 重拍和隔离

示例配置：

- 每个镜头最多 3 次 take。
- 全部失败后最多再生 1 次（拉远、保持单人；语音类问题会去掉台词）。
- 再生之后仍然失败，镜头进入 `quarantine/`。
- 一部片子里隔离镜头达到 3 个，或达到镜头数的 15%，整片状态变成 `quarantined`。已通过的镜头仍然写进合成计划。
- 一条故事在改编或运行中抛错，写成 `story_quarantine.json`，循环继续。

dry-run 的示例配置会在 `sample-market-rain` 的第 4 镜注入一个重拍也消不掉的手部缺陷。这是为了让隔离路径被真正走到，不是画质模型。真实 GPU 运行不读取这段注入。

台账 `data/ledger.json` 记下已经完成或隔离的故事，避免一夜里反复撞同一条。`--requeue` 会忽略台账再跑。

## 退出码

渲染器的退出码 0 不是通过。审核命令的退出码 0 也不是通过。报告里的 `passed` 和运行日志里的 `status` 才是结果。

审核报告带 `renderer_exit_ignored: true`。dry-run 里那个被注入失败的镜头，退出码仍是 0，`passed` 是 false。

## 审核项

v0 能做的是结构化检查，不是完整的视觉模型。

| 检查 | v0 实际做什么 |
| --- | --- |
| 分辨率 | 视频必须是 416×736，首帧必须是 768×1344 |
| 时长 | 帧数必须在 17n+5 的可用窗口里，并等于计划 |
| 首帧锁定 | 视频参考里必须有已通过的首帧 |
| 参考图范围 | 不得出现这一镜没有声明的素材 |
| 脸一致性 | 比较角色静帧版本令牌。这不是人脸嵌入，换真模型时替换这一项 |
| 手部特写 | 成片被标成手部特写，或景别本身要求手部特写。提示里的「不给手部特写」是约束，不算要求 |
| 他/她 | 同一镜台词里同时出现单数的他和她。复数「他们」先去掉 |
| 台词堆叠 | 一镜多句或多人，容易念成旁白 |
| 长句 | 默认只警告。单人长句会读错，这个问题没有解决 |
| 静音 | 有台词却没有语音，或没有台词却有明显人声 |
| 画面缺陷 | 后端标出的黑场一类问题 |
| 提示契约 | 六段齐全，summary 带 `keyframe completion` |
| 尾帧 | 只有同一场、同一动作组的延长才合法 |

这些钩子的作用是把失败留下来。它们不是「语音和手已经修好了」的声明。
